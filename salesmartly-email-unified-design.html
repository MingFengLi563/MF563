新增功能：归属邮箱支持配置单独的代发邮箱。用户添加归属邮箱后，可为每个归属邮箱配置一个实际发送用的代发邮箱，实现"归属关系"与"实际发送"的分离。

📊 现状分析

当前两个独立入口

维度 📤 Email 群发 📨 Email 三方代发 (EDM)
入口位置 消息群发 → Email 第三方代发 → EDM
收件人来源 有归属指定邮箱账号的联系人 有邮箱字段的任意联系人
联系人渠道 只能是 Email 渠道 可以是 Messenger/WhatsApp 等其他渠道
发送人 自动使用联系人归属邮箱
v2.0: 支持配置代发邮箱		 手动指定统一发送人邮箱
使用场景 客服对已分配客户进行邮件跟进 营销团队对潜在客户批量发送 EDM
数据隔离 按客服账号隔离 统一发送，无隔离

❌ 问题 1：入口分散

用户需要根据场景选择不同入口，容易混淆。营销人员可能误用 Email 群发，客服可能找不到 EDM 入口。

❌ 问题 2：规则不透明

发送人选择规则在两个入口完全不同，用户容易选错发送邮箱，导致邮件从错误账号发出。

❌ 问题 3：无法混合使用

同一批联系人中，部分有归属邮箱、部分只有邮箱字段，无法在同一计划中统一发送。

❌ 问题 4：预览不清晰

发送前无法清晰预览每封邮件的实际发送人和收件人，容易出错。

⚠️ 使用建议
  • 统一品牌形象：所有客服使用统一的 noreply@company.com 或 support@company.com 作为代发邮箱
  • 提高送达率：使用经过 SPF/DKIM 验证的专业代发邮箱，避免个人邮箱被标记为垃圾邮件
  • 保持归属关系：即使使用代发邮箱，客户归属关系仍记录在原客服账号下，便于后续跟进
  • 灵活配置：可为不同客服配置不同代发邮箱（如销售团队用 sales@，客服团队用 support@）

💡 整合方案

✅ 核心设计理念

「智能模式切换 + 统一发送流程 + 代发邮箱映射」

根据用户选择的联系人类型，自动推荐发送模式；支持归属邮箱配置代发邮箱；统一发送配置和预览界面。

模式选择设计（v2.0）

🎯
智能模式（推荐）
系统根据联系人类型自动分配发送规则，最大化送达率
  • 有归属邮箱 → 使用归属邮箱或其配置的代发邮箱
  • 仅有邮箱字段 → 使用统一发送人
  • 自动优化发送策略
  • 适合混合联系人列表
👤
归属邮箱模式
仅选择有归属邮箱的联系人，使用各自归属邮箱（或代发邮箱）发送
  • 100% 使用归属邮箱体系
  • 自动应用代发邮箱配置
  • 适合客服跟进场景
  • 保持对话连续性
📢
统一代发模式
手动指定发送人邮箱，对所有联系人统一发送
  • 自由选择发送邮箱
  • 适合营销 EDM 场景
  • 支持所有有邮箱的联系人
  • 品牌统一形象
⚠️ 模式选择建议
  • 智能模式：联系人列表混合时首选，系统自动处理规则差异
  • 归属邮箱模式：客服团队对已分配客户进行跟进时使用
  • 统一代发模式：营销团队发送产品更新、活动通知时使用

🔄 交互流程设计

1
选择联系人
支持多种选择方式：手动勾选、条件筛选、导入列表。系统实时统计联系人类型分布（有归属邮箱数量、仅有邮箱字段数量）。
2
智能推荐模式
根据联系人构成自动推荐发送模式，并显示推荐理由。用户可手动切换其他模式，系统实时刷新预览数据。
3
配置发送人
根据选择的模式显示不同配置项：智能模式/归属模式显示关联邮箱列表（含代发邮箱映射），统一代发模式显示发送人选择器。
4
编辑邮件内容
统一邮件编辑器，支持富文本、变量插入、附件上传。提供预览功能，可查看任意联系人收到的邮件效果。
5
发送前预览
展示发送摘要：总数量、按发送人分组统计（显示归属邮箱→代发邮箱映射）、预计发送时间。支持抽样预览具体邮件的发送人和收件人。
6
确认发送
二次确认弹窗，显示关键信息摘要。发送后跳转任务详情页，实时追踪发送进度和送达状态。

🛠️ 技术实现建议

前端框架
Vue 3 / React + TypeScript，使用组件化开发模式选择器和预览模块
状态管理
Pinia / Redux 管理联系人选择、模式配置、发送人状态、代发邮箱映射
实时统计
WebSocket 推送联系人筛选结果，避免全量数据传输
后端 API
RESTful API 设计，支持批量操作和异步任务队列
邮件队列
Redis + Bull 处理发送队列，支持优先级和重试机制
数据验证
Zod / Joi 验证请求数据，确保发送规则正确执行

  campaign: {

    mode: "smart" | "assigned" | "unified",  // 发送模式
    status: "draft" | "scheduled" | "sending" | "completed"
  },
  
  // 联系人分组统计
  contacts: {
    total: 1258,
    withAssignedEmail: 856,    // 有归属邮箱
    withEmailField: 402,       // 仅有邮箱字段
    invalid: 0                 // 无有效邮箱
  },
  
  // 邮箱配置（v2.0 新增）
  emailConfig: {
    // 客服邮箱映射表
    agentEmails: [
      {
        agentId: "u1",
        agentName: "Alice Zhang",
        assignedEmail: "alice@company.com",
        delegateEmail: "noreply@company.com",  // 代发邮箱（可选）
        useDelegate: true                       // 是否使用代发
      },
      {
        agentId: "u2",
        agentName: "Bob Li",
        assignedEmail: "bob@company.com",
        delegateEmail: "support@company.com",
        useDelegate: true
      },
      {
        agentId: "u3",
        agentName: "Carol Wang",
        assignedEmail: "carol@company.com",
        delegateEmail: null,
        useDelegate: false
      }
    ],
    // 统一代发邮箱列表
    unifiedEmails: [
      "marketing@company.com",
      "support@company.com",
      "info@company.com"
    ]
  },
  
  // 发送人配置
  senders: {
    // 智能模式/归属模式：按客服分组（v2.0 显示实际发送邮箱）
    byAgent: [
      { 
        agentId: "u1", 
        assignedEmail: "alice@company.com",
        actualSender: "noreply@company.com",  // 实际发送邮箱
        count: 285 
      },
      { 
        agentId: "u2", 
        assignedEmail: "bob@company.com",
        actualSender: "support@company.com",
        count: 312 
      },
      { 
        agentId: "u3", 
        assignedEmail: "carol@company.com",
        actualSender: "carol@company.com",  // 未配置代发，使用归属邮箱
        count: 259 
      }
    ],
    // 统一代发模式：指定发送邮箱
    unified: "marketing@company.com"
  },
  
  // 发送规则引擎（v2.0）
  sendingRules: {
    // 智能模式规则
    smart: (contact, emailConfig) => {
      if (contact.assignedEmail) {
        // 查找该归属邮箱对应的配置
        const agentConfig = emailConfig.agentEmails.find(
          a => a.assignedEmail === contact.assignedEmail
        );
        // 如果配置了代发邮箱，使用代发；否则使用归属邮箱
        const actualSender = agentConfig?.useDelegate && agentConfig?.delegateEmail
          ? agentConfig.delegateEmail
          : contact.assignedEmail;
        return { 
          sender: actualSender, 
          assignedEmail: contact.assignedEmail,
          mode: "assigned" 
        };
      } else if (contact.emailField) {
        return { sender: config.unifiedEmail, mode: "unified" };
      }
      return null; // 跳过无效联系人
    },
    
    // 归属模式规则（v2.0）
    assigned: (contact, emailConfig) => {
      if (!contact.assignedEmail) return null;
      const agentConfig = emailConfig.agentEmails.find(
        a => a.assignedEmail === contact.assignedEmail
      );
      const actualSender = agentConfig?.useDelegate && agentConfig?.delegateEmail
        ? agentConfig.delegateEmail
        : contact.assignedEmail;
      return { 
        sender: actualSender, 
        assignedEmail: contact.assignedEmail,
        mode: "assigned" 
      };
    },
    
    // 统一代发模式规则
    unified: (contact) => {
      if (!contact.emailField) return null;
      return { sender: config.unifiedEmail, mode: "unified" };
    }
  }
}

⚠️ 风险与应对

⚠️ 风险 1：发送规则错误

风险：代发邮箱映射配置错误，导致邮件从错误邮箱发出

应对：发送前强制预览确认（显示归属→代发映射），首次发送限制小批量测试，记录完整发送日志便于追溯

⚠️ 风险 2：性能问题

风险：大批量联系人实时统计导致页面卡顿

应对：使用 WebSocket 推送预计算结果，前端只展示不计算，支持分页加载

⚠️ 风险 3：用户混淆

风险：用户不理解归属邮箱和代发邮箱的区别

应对：添加新手引导弹窗、工具提示（tooltip）、帮助文档，在配置界面清晰说明两者关系

⚠️ 风险 4：数据迁移

风险：历史群发计划数据格式不兼容

应对：向后兼容旧数据格式，新界面支持查看历史计划但不支持编辑
