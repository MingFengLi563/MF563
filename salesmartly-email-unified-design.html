📦 版本规划

✅ v3.0 线上第一版（当前）

流程：用户手动选择发送模式 → 系统筛选符合条件的联系人

模式：归属邮箱发送 / 统一邮箱代发（2 选 1）

优势：逻辑简单清晰，用户完全掌控，开发成本低

🔮 v4.0 智能模式（后续迭代）

流程：用户先选择联系人 → 系统智能推荐发送模式

模式：智能模式 / 归属邮箱模式 / 统一代发模式（3 选 1）

优势：自动化程度高，适合混合联系人列表

📊 现状分析

维度 📤 Email 群发 📨 Email 三方代发 (EDM)
入口位置 消息群发 → Email 第三方代发 → EDM
收件人来源 有归属指定邮箱账号的联系人 有邮箱字段的任意联系人
发送人 自动使用联系人归属邮箱
v3.0: 支持配置代发邮箱		 手动指定统一发送人邮箱
使用场景 客服对已分配客户进行邮件跟进 营销团队对潜在客户批量发送 EDM

❌ 问题 1：入口分散

用户需要根据场景选择不同入口，容易混淆。

❌ 问题 2：规则不透明

发送人选择规则在两个入口完全不同，用户容易选错发送邮箱。

❌ 问题 3：无法混合使用

同一批联系人中，部分有归属邮箱、部分只有邮箱字段，无法在同一计划中统一发送。

❌ 问题 4：预览不清晰

发送前无法清晰预览每封邮件的实际发送人和收件人。

🔗 归属邮箱与代发邮箱配置

⚡ 核心概念：归属关系 ≠ 实际发送
归属邮箱alice@company.com
⬇️ 配置代发
代发邮箱noreply@company.com
效果：客户归属 Alice，实际从 noreply 发送
归属邮箱bob@company.com
⬇️ 配置代发
代发邮箱support@company.com
效果：客户归属 Bob，实际从 support 发送
归属邮箱carol@company.com
⬇️ 未配置代发
代发邮箱（使用归属邮箱本身）
效果：直接使用 carol@company.com 发送
⚠️ 使用建议
  • 统一品牌形象：所有客服使用统一的 noreply@或 support@作为代发邮箱
  • 提高送达率：使用经过 SPF/DKIM 验证的专业代发邮箱
  • 保持归属关系：即使使用代发邮箱，客户归属关系仍记录在原客服账号下
  • 灵活配置：可为不同客服配置不同代发邮箱（销售用 sales@，客服用 support@）

💡 整合方案（v3.0 线上第一版）

✅ 核心设计理念

「用户手动选择模式 → 系统筛选联系人」

用户先选择发送模式（归属邮箱发送 / 统一邮箱代发），系统根据选择的模式自动筛选符合条件的联系人，支持配置代发邮箱。

发送模式选择（2 选 1）

👤
归属邮箱发送
使用客服归属邮箱（或配置的代发邮箱）发送，适合客服跟进场景
  • 100% 使用归属邮箱体系
  • 自动应用代发邮箱配置
  • 仅显示有归属邮箱的联系人
  • 保持对话连续性和客户归属关系
  • 推荐场景：客服对已分配客户进行邮件跟进
📢
统一邮箱代发
手动指定发送人邮箱，对所有联系人统一发送，适合营销 EDM 场景
  • 自由选择发送邮箱
  • 显示所有有邮箱字段的联系人
  • 支持 Messenger/WhatsApp 等其他渠道联系人
  • 品牌统一形象
  • 推荐场景：营销团队发送产品更新、活动通知
⚠️ 模式选择建议
  • 归属邮箱发送：客服团队对已分配客户进行跟进时使用，邮件从客服归属邮箱（或代发邮箱）发出，客户感知是专属客服在联系
  • 统一邮箱代发：营销团队发送产品更新、活动通知、EDM 营销时使用，邮件从统一邮箱（如 marketing@、noreply@）发出，品牌形象统一

🔄 交互流程设计（v3.0）

1
选择发送模式
用户手动选择发送模式：归属邮箱发送 / 统一邮箱代发。系统显示模式说明和推荐场景，帮助用户决策。
2
筛选联系人
系统根据选择的模式自动筛选符合条件的联系人：归属模式仅显示有归属邮箱的联系人，代发模式显示所有有邮箱字段的联系人。支持进一步条件筛选和手动勾选。
3
配置发送人
归属模式：显示关联邮箱列表（含代发邮箱映射），可调整个别客服的代发配置。代发模式：选择统一发送邮箱。
4
编辑邮件内容
统一邮件编辑器，支持富文本、变量插入、附件上传。提供预览功能，可查看任意联系人收到的邮件效果。
5
发送前预览
展示发送摘要：总数量、按发送人分组统计（显示归属邮箱→代发邮箱映射）、预计发送时间。支持抽样预览具体邮件的发送人和收件人。
6
确认发送
二次确认弹窗，显示关键信息摘要。发送后跳转任务详情页，实时追踪发送进度和送达状态。
💡 v3.0 vs v4.0 流程对比
v3.0（当前）：选择模式 → 筛选联系人 → 配置发送人 → 编辑内容 → 预览 → 发送
v4.0（智能模式）：选择联系人 → 智能推荐模式 → 确认/切换模式 → 配置发送人 → 编辑内容 → 预览 → 发送

🛠️ 技术实现建议

前端框架
Vue 3 / React + TypeScript，组件化开发模式选择器和预览模块
状态管理
Pinia / Redux 管理联系人选择、模式配置、发送人状态、代发邮箱映射
实时统计
WebSocket 推送联系人筛选结果，避免全量数据传输
后端 API
RESTful API 设计，支持批量操作和异步任务队列
邮件队列
Redis + Bull 处理发送队列，支持优先级和重试机制
数据验证
Zod / Joi 验证请求数据，确保发送规则正确执行

核心数据结构

{
  campaign: {
    id: "camp_xxx",
    name: "2026 年 4 月产品更新",
    mode: "assigned" | "unified",  // v3.0: 2 种模式
    status: "draft" | "scheduled" | "sending" | "completed"
  },
  emailConfig: {
    agentEmails: [
      {
        agentId: "u1",
        agentName: "Alice Zhang",
        assignedEmail: "alice@company.com",
        delegateEmail: "noreply@company.com",
        useDelegate: true
      }
    ]
  },
  sendingRules: {
    assigned: (contact, emailConfig) => {
      if (!contact.assignedEmail) return null;
      const agentConfig = emailConfig.agentEmails.find(a => a.assignedEmail === contact.assignedEmail);
      const actualSender = agentConfig?.useDelegate && agentConfig?.delegateEmail
        ? agentConfig.delegateEmail : contact.assignedEmail;
      return { sender: actualSender, assignedEmail: contact.assignedEmail, mode: "assigned" };
    },
    unified: (contact) => {
      if (!contact.emailField) return null;
      return { sender: config.unifiedEmail, mode: "unified" };
    }
  }
}

📅 实施路线图

Phase 1 - 1-2 周
邮箱配置管理界面
新增"邮箱账号管理"页面，支持为每个归属邮箱配置代发邮箱。实现代发邮箱验证状态显示、下拉选择器组件。
Phase 2 - 2-3 周
前端界面重构
统一群发入口，实现模式选择器（2 选 1）、联系人筛选、发送人配置组件。在预览界面显示归属邮箱→代发邮箱映射关系。
Phase 3 - 2-3 周
后端规则引擎
实现发送规则引擎，支持代发邮箱映射。优化邮件队列，支持按实际发送邮箱分组批量发送。
Phase 4 - 1 周
预览与验证
实现发送前预览功能，支持抽样查看具体邮件。添加代发邮箱验证检查、邮箱格式验证、发送限额检查。
Phase 5 - 1 周
测试与上线
内部测试、灰度发布、用户反馈收集。保留旧入口 30 天，引导用户迁移到新界面。
📦 版本规划
v3.0（当前）：Phase 1-5 完整实现，7-8 周上线
v4.0（智能模式）：在 v3.0 基础上增加智能推荐算法，额外 2-3 周开发

📊 成功指标

  • 错误率降低：发送人选择错误率从 15% 降至 5% 以下

  • 用户满意度：NPS 评分从 35 提升至 50+
  • 客服工单减少：相关咨询工单减少 40%
